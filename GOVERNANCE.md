# Project governance

DAGrail is maintained in the open. CongBao is the initial maintainer and release
steward. Design authority comes from reviewed repository history, compatibility
contracts, and accepted pull requests—not private chat transcripts.

Contributors may propose issues, documentation, tests, providers, or core changes.
Changes to journal authority, lifecycle semantics, effect receipts, compatibility,
security boundaries, or release gates require an ADR or equivalent design explanation,
migration impact, and evidence proportional to risk. Provider and adapter additions
must preserve the host-neutral core.

Maintainers may merge changes after review and passing required checks. No contributor
is entitled to merge solely by authorship. Security reports follow SECURITY.md. Project
conduct follows CODE_OF_CONDUCT.md.

If stewardship expands, maintainers will document nomination, voting, inactivity, and
succession rules before relying on them. Until then, final release authority remains
with the initial maintainer, while technical decisions and their evidence stay public.
